# P5 Testing Implementation Plan

> **For agentic workers:** implement task by task; steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Derive tests from requirements and design (one file per use case, one test per acceptance criterion), run them in Docker, triage failures into test fixes or code bugs, apply code fixes through the code agent, gate P5 by code.

**Architecture:** Plain code plans one test file per use case; Haiku workers write them in parallel rounds (attempt 3 Sonnet); one typecheck and test run per round; a Sonnet test agent triages assertion failures and reports findings through two tools; Apply fix runs the code agent. The orchestrator gains P5 as a fourth chat phase with a gate read from `.aise/checks/P5.json`.

**Spec:** `docs/superpowers/specs/2026-11-20-p5-testing-design.md` (read it first; section numbers below refer to it). P4 counterparts to mirror: `codegen/plan.ts`, `codegen/generate.ts`, `agents/code-worker.ts`, `agents/code.ts`, `core/code-state.ts`, `orchestrator/p4.ts`, `components/CodePanel.svelte`.

## Global Constraints

- Server code under `src/lib/server` uses relative imports and `process.env` only; no `$lib`, `#lib`, `$env`. UI imports `src/lib` with `#lib/*`.
- Opus is not used by P5. Worker `claude-haiku-5-5`, escalation, test agent and code agent `claude-sonnet-5-5`. Lowest effort that works.
- Worker concurrency cap 4, worker turn limit 8, attempts 2 Haiku then 1 Sonnet. Test agent turn limit 30.
- Cost guard $2 per generation run: no new worker, no triage, run `failed`.
- Test file paths `test/UC-xxx.test.ts` and `test/REQ-xxx.test.ts`. Test names per spec 5.2.
- Test hash covers `test/`. Checks file `.aise/checks/P5.json`. P5 artefact hash (run bookkeeping, discard guard) is sha256 of the code hash and the test hash, because Apply fix runs change `src/`.
- The test agent and test workers never read `src/` (existing `READ_DENY`). The code agent never writes `test/` (existing scope).
- No hyphens or dashes as punctuation in UI copy.
- Verification gate before every commit: `npm run check && npm run lint && npm test`; Task 9 also `npm run test:docker`.
- Decision entries in `docs/decisions.md` (date 2026-11-20, what, why) in the task that implements the decision.

## Review Focus

1. A test worker or the test agent asking for `src/...` gets a tool error (Task 4 test).
2. A suite level failure (import error, syntax error) is never green, counts as a file problem and retries the file; a plain assertion failure does not retry (Task 5).
3. A hand edit under `src/` or `test/` turns "All tests pass" to "out of date" (Task 6).
4. Coverage counts a manual todo as covered, never as passed; a test named for a criterion that does not exist (`REQ-999 AC9`, `REQ-001 AC7` when REQ-001 has 2) counts for nothing (Task 2).
5. Discarding an Apply fix run restores `src/`; discard refuses when code or tests changed since the run (Task 6).
6. Triage cannot weaken tests silently: every test it changes appears in `testFixes` with a reason (Task 5).

### Task 5: Test generation pipeline with triage

Model: `sonnet`, effort `high`.

**Files:**
- Create: `src/lib/server/testgen/generate.ts`, `generate.test.ts`

**Interfaces:**
- `generateTests(opts: { ctx; reqs; design; onEvent: (e: GenerateEvent) => void; run?; checks?: typeof runTestChecks; codeModel?: (ctx) => Promise<CodeModel>; costLimitUsd? }): Promise<RunResult & { files: Record<string, FileStatus>; checked: boolean }>`; reuses `FileStatus` and `GenerateEvent` from `codegen/generate.ts` (triage streams as the `wiring` kind or a renamed general kind; builder's choice, keep P4 working).
- Shared `pool` helper moved to a small module if both pipelines need it.

Algorithm (spec 5.3, 5.4): code model once; round 1 all plans (cap 4); after each round `checks`; a file is ok with no tsc error in its path, no `suite` entry for its file, and a test or todo titled for every criterion; problems listed per file; retries as P4; then, if any test fails, the test agent with `triageBrief` (turn limit 30); final `checks` merges the run's findings. Cost summed.

- [ ] Failing tests with fake `run`, `checks`, `codeModel`: all ok without triage; concurrency cap; suite error retries the file, assertion failure does not (Review Focus 2); missing criterion title retries; escalation on attempt 3, failed after 3, run `done`; triage runs only on failures and its `report_test_fix` entries land in the checks (Review Focus 6); cost guard skips triage, `failed`; thrown Docker error ends `failed`.

**Interfaces:**
- `ChatPhase` gains `'P5'`. `checkGate('P5', ...)` with checks `Tests exist`, `Every must criterion has a test`, `Tests type check`, `All tests pass`; the last two `out of date` when stored code or test hash differs.
- `Orchestrator.generateTests(name)`, `checkTests(name)`, `applyFix(name, findingId)`; `sendMessage`, `approve`, `stillValid`, `updateStale`, `discardLastRun` accept P5.
- Snapshot gains `gates.P5`, `chat.P5`, `testChecks: TestChecks | null`, `staleTestIds: string[]`; `files` includes `test/`; `codegen` covers P5 generation runs.
- `Deps.generateTests?`, `Deps.testChecks?` for tests; `agents` gains `test`.

Rules: P5 actions need P4 approved and not stale. Approving P4 on a project without `test/` files starts a generation run. P5 artefact hash is `p5Hash`. Approve stores `reqHashes` and `useCaseHashes` (use cases and sequences: name, reqIds, messages). Stale when either differs; Update starts the test agent with `testUpdateBrief`. Apply fix: finding must be open; run phase P5, agent `code`, brief `fixBrief`; ends with `runCodeChecks` and `runTestChecks`. Every P5 run ends with `runTestChecks`. `recover()` settles P5.

- [ ] Failing tests: auto start on P4 approval only without tests; refusals when P4 not approved, stale, or tests exist (generate); gate pass and out of date after a `src/` or `test/` edit (Review Focus 3); approve with override; stale on criterion change and on sequence change, not on description change; Update and Still valid; Apply fix refreshes both checks files and refuses a resolved finding; discard of an Apply fix run restores `src/` and refuses after a later edit (Review Focus 5); recovery; existing P1, P2, P4 tests stay green.
- [ ] Implement; `npm test` passes.
