# Week 1: foundation, P1 and P2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A developer creates the to-do project in the browser, describes the idea, answers the requirements agent's questions, approves P1, and gets an approved P2 design with use case, class, sequence and deployment diagrams rendered from `design.json`.

**Architecture:** One SvelteKit package. Deterministic core (zod schemas, type normalisation, design validation, Mermaid rendering, project store) under `src/lib/server/core/`; an in process tool registry the agents call; our own agent loop on the Anthropic SDK under `src/lib/server/agents/`; a plain code orchestrator under `src/lib/server/orchestrator/` that owns phase state and gates and streams events to the UI over SSE. MCP server, trace, P3 to P7 are later plans.

**Tech Stack:** TypeScript, SvelteKit (Svelte 5 runes, adapter-node), Vitest (jsdom and Testing Library for UI components), zod 4, `typescript` (compiler API for type parsing), `@anthropic-ai/sdk`, `mermaid` (browser only), `@lucide/svelte`, fontsource (Geist, Geist Mono, Instrument Serif), ESLint and Prettier, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-04-ai-se-environment-design.md`. Sections 3 to 8 and 10 drive this plan. Weeks 2 and 3 get their own plans after this one lands.

## Global Constraints

- Node 22, npm, one package at the repo root. Projects live in `showcases/<name>/`; root overridable with `AISE_PROJECTS_DIR`.
- Agents never write Mermaid; diagrams come only from `design.json` through `core/render/`.
- Every JSON artefact is validated with zod on every write; an invalid write fails the tool call and returns the errors to the agent.
- Models: requirements `claude-sonnet-5-5`, design `claude-opus-5-5`, gate summaries `claude-haiku-5-5`. Never append date suffixes to model IDs.
- Opus 5.5 and Sonnet 5.5: no forced `tool_choice` (`auto` only), no `thinking: {type: "disabled"}`, no assistant prefill, effort set explicitly in `output_config.effort`.
- Agent loop turn limit 30. API errors retry 3 times with backoff (SDK `maxRetries: 3`), then the run fails visibly.
- Secrets only in `.env` (gitignored). Optional `ANTHROPIC_API_KEY_FALLBACK`.
- IDs: `REQ-001`, `Q-001`, `ACT-001`, `UC-001`, `DSN-001` (classes, components and nodes share one sequence), `SEQ-001`. Three digits, zero padded.
- Generated docs carry the first line `<!-- generated by AISE from .aise/*.json, do not edit -->`.
- Docs kept current in the same PR: `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md`, `docs/decisions.md`, `docs/design-system.md`, `AGENTS.md` commands.
- Client code imports from `$lib/server/**` with `import type` only (SvelteKit rejects runtime imports there).
- Svelte files: Svelte 5 runes only; run the Svelte MCP `svelte-autofixer` on every `.svelte` file before committing.
- UI: screens use only `$lib/ui` components and design tokens (Tasks 11 and 12); no raw colours, font sizes, spacing or durations. The guardrail test enforces this. Both light and dark themes must work.

## Review Focus

1. A second chat message or an Approve click while a run is active: rejected with a visible message, never two runs on one project (test in Task 10).
2. Server restart during a run: the phase must not stay `running` forever; the run is marked failed with "server restarted" (test in Task 10).
3. Generic and quoted types in diagrams (`Promise<Task[]>`, `Record<string, number>`, a label with `"`): Mermaid output still parses (test in Task 5).
4. The model calls an unknown tool, a tool it is not allowed, sends input that fails zod, or loops past 30 turns: tool errors go back as `is_error` results, the turn limit fails the run, artefacts written so far stay discardable (test in Task 8).
5. Path traversal through a project name (`../x`) or a relative path (`../../etc`): rejected before any file access (test in Task 6).
