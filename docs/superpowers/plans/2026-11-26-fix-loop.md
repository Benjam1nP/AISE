# Fix Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One P5 run, the fix loop, in which the test agent and the code agent hand findings to each other until the tests are green or a stop rule fires, with every handoff visible.

**Architecture:** A plain code pipeline `src/lib/server/testgen/fix-loop.ts` (style of `generateTests`) runs triage, fix and checks per round, giving each step its own `ToolContext.agent`. The orchestrator starts it from a Tests tab action or right after a test generation run that left code bug findings, on the same claim. Handoffs travel as `AgentMessage` values: published as `agent_message`, logged in `events.jsonl`, appended to the P5 chat with `from` and `to`.

**Tech Stack:** TypeScript, SvelteKit (Svelte 5), zod, Vitest (projects `node` and `jsdom`), Anthropic SDK through our `runAgent`.

**Spec:** `docs/superpowers/specs/2026-11-26-fix-loop-design.md`

## Global Constraints

- Server code under `src/lib/server` uses relative imports and `process.env` only; UI imports `#lib/*`.
- Max 3 rounds; cost guard $3 (soft, checked between steps); a finding (keyed by file plus test name) gets at most 2 fix attempts.
- Step turn limits: triage 30, code fix 40.
- `report_fix_result` outcomes exactly `'fixed' | 'needs_design_change' | 'test_looks_wrong'`; only for the code agent in a fix loop run (`ctx.fixLoop === true`); in `RUN_ONLY_TOOLS`.
- New schema fields are optional so old `.aise` files still parse: `RunMeta.fixLoop`, `ChatEntry.from`, `ChatEntry.to`, `RunFindings.fixResults` (default `[]` when absent).
- Prose and copy: no em dashes, en dashes or decorative hyphens (org rule).
- Gate before every commit of a task: targeted tests; full gate (`npm run check`, `npm run lint`, `npm test`) once at the end.

## Review Focus

1. A fix loop run discarded after it changed both `src/` and `test/`: everything, including both checks files, is back as before. Test in Task 4.
2. Two fast clicks on Fix automatically, or a click while generation hands over to the loop: the second gets `ConflictError` `run_active`, never a second run. Test in Task 4.
3. The code agent calls `report_fix_result` with an unknown finding ID or one not handed to it this round: tool error, nothing stored. Test in Task 1.
4. A server restart during a loop: `recover` marks it failed like any run, and the next Fix automatically works. Test in Task 4.
5. A chat file written before this change (no `from`, `to`) and a findings file without `fixResults` still load. Test in Task 1.

### Task 3: The loop pipeline

**Files:**
- Create: `src/lib/server/testgen/fix-loop.ts`
- Test: `src/lib/server/testgen/fix-loop.test.ts` (mock `run`, `codeChecks`, `testChecks` as `generate.test.ts` does)

**Interfaces:**
- Consumes: Task 1 (`readRunFindings`, `FixResult`, `ToolContext.fixLoop`, `handedOver`, `AgentRole`), Task 2 briefs, `unexplainedFailures`, `findingOpen`, `failureOf` (wherever the orchestrator imports them today), `snapshotTests`, `recordUnreportedFixes`, `p5Hash`, `runCodeChecks`, `runTestChecks`.
- Produces:
  - `type AgentMessage = { from: AgentRole; to: AgentRole; text: string; findingIds: string[] }`
  - `fixLoop(opts: { ctx: ToolContext; agents: { test: AgentDef; code: AgentDef }; run: typeof runAgent; codeChecks: typeof runCodeChecks; testChecks: typeof runTestChecks; onEvent: (e: AgentEvent) => void; onMessage: (m: AgentMessage) => void; costLimitUsd?: number; maxRounds?: number }): Promise<RunResult & { checked: boolean }>`
  - `FIX_LOOP_COST_LIMIT_USD = 3`, `FIX_LOOP_ROUNDS = 3`, `MAX_FIX_ATTEMPTS = 2`

Algorithm (state per loop: `attempts: Map<fileTest, number>`, `declined: Set<fileTest>`, `disputed: Map<fileTest, reason>`, `triaged: Set<file>`):
1. Start from `testChecks(ctx)` stored state (read the stored checks; the caller guarantees they are current).
2. Each round: record `p5Hash` before.
   a. Unexplained failures or disputed findings non empty → triage step with `{ ...ctx, agent: 'test' }`, def `agents.test`, 30 turns, brief `triageBrief(failures, logTail, { keep: [...triaged], disputed })`, wrapped in `snapshotTests`/`recordUnreportedFixes`. Files it changed that are already in `triaged` → stop after this step (`done`, message from `checks` to `test`: "<file> was changed twice by triage; it needs the developer."). Add changed files to `triaged`. Clear `disputed` (a disputed finding reported again stays open but is added to `declined`). Then `testChecks` to merge the triage reports.
   b. Hand over: open findings, test file exists, not declined, attempts below 2. Also include `broken` (typecheck errors and drift items from the last `codeChecks`, when not clean). None and no `broken` → go to the stop check. `onMessage({ from: 'test', to: 'code', text: 'Please fix F-1, F-2: <one line explanation each>', findingIds })`.
   c. Fix step with `{ ...ctx, agent: 'code', fixLoop: true, handedOver: ids }`, def `{ ...agents.code, tools: [...agents.code.tools, 'report_fix_result'] }`, 40 turns, `fixLoopBrief`. Increment attempts. Read this round's `fixResults`: `needs_design_change` and `test_looks_wrong` → `declined`; `test_looks_wrong` also → `disputed`. `onMessage({ from: 'code', to: 'test', text: one line per finding ("F-1 fixed", "F-2 needs a design change: …", "F-3 test looks wrong: …"), findingIds })`.
   d. `codeChecks(ctx)` then `testChecks(ctx)`. `onMessage({ from: 'checks', to: 'test', text: 'Round n: x passed, y failed', findingIds: [] })`.
3. Stop checks after each step, in this order: agent step failed with `reason: 'error'` → `failed`; a check timed out or threw → `failed`; cost ≥ limit → `failed` "Cost limit of $3.00 exceeded ($x spent); the fix loop stopped."; no test fails and code checks clean → `done`; `p5Hash` unchanged over the round → `done`; nothing to hand over, nothing unexplained, nothing disputed → `done`, or `failed` "The fix loop left the code with typecheck errors or drift" when the last code checks are not clean; round = max → same as the previous rule.
4. Return `checked: true` iff the last step was 2d; usage and cost summed over steps; `text` a short summary (rounds, fixed, open, declined, test changes).

- [ ] **Step 1: Failing tests** (one each): green after round 1 (no triage call, one code call, `checked: true`); triage runs in round 2 when the fix leaves a new unexplained failure; `needs_design_change` is never handed over again and the loop ends `done`; `test_looks_wrong` goes to triage next round with the reason in the brief; a finding still failing gets a second attempt with the retry line and never a third; second triage change to the same file stops; stops after 3 rounds; a round with an unchanged `p5Hash` stops; cost guard stops before the next step; triage step ctx has `agent: 'test'`, fix step `agent: 'code'`, `fixLoop: true`, `handedOver` the IDs; typecheck errors after a fix go back in the next brief and end `failed` if still there at the end; messages are emitted in order test→code, code→test, checks→test.
- [ ] **Step 2:** `npx vitest run src/lib/server/testgen/fix-loop.test.ts` fails.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Passes.
- [ ] **Step 5:** Commit `feat(p5): fix loop pipeline`.
